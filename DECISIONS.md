# Decisions

Choices made where the plan was ambiguous, newest last.

## Phase 0

- **Local SQL Server image:** `mcr.microsoft.com/mssql/server:2022-latest` with `platform: linux/amd64` under Rosetta. The plan's alternative, `azure-sql-edge`, was retired by Microsoft in September 2025 and no longer gets updates.
- **SA password** lives in a git-ignored root `.env` file, which docker-compose reads automatically. Compose refuses to start if it's missing.
- **Flutter state management:** `provider` (simpler of the two options in the plan).
- **Flutter platforms:** iOS and Android only (no web/desktop folders).
- **Flutter bundle ID:** `com.doyouknowball.dykb`.
- **.NET 10 instead of .NET 8:** .NET 8 support ends November 10, 2026. .NET 10 is the current LTS (supported to November 2028) and runs on Azure App Service. Pinned via `api/global.json`.
- **API port 5050, not 5000:** macOS AirPlay Receiver listens on port 5000 and returns 403s. The API binds to `http://localhost:5050` (Android emulator: `http://10.0.2.2:5050`).
- **Swagger UI is on in every environment**, so the deployed API can be used through Swagger (an MVP requirement). It's at `/swagger`.
- **No HTTPS redirection in the app:** locally it's HTTP only; in prod, App Service "HTTPS Only" handles it.
- **Swashbuckle** for Swagger rather than the template's `Microsoft.AspNetCore.OpenApi`, since it serves the UI and the bearer "Authorize" button.
- **Dev secrets** (`Jwt:Key`, `ConnectionStrings:Default`) live in .NET user-secrets, outside the repo.
- **JWT lifetime:** 7 days (`Jwt:ExpiryMinutes` = 10080), because there are no refresh tokens in the MVP.
- **`GET /health`** added now (anonymous), not in Phase 4.
- **`System.Security.Cryptography.Pkcs` pinned to 10.0.13** to override a vulnerable 9.0.11 version that the SQL client pulls in.

## Phase 1

- **(Superseded below by quiz attempts.)** **`sessionToken` is required in `POST /games`** (added to the contract). It's an encrypted, 1-hour token (ASP.NET Data Protection) recording the user, category and the exact question IDs that `/quiz` served. Submissions must answer exactly those questions once each, so players can't choose which questions to be scored on or submit with someone else's quiz. **Known gap:** a token can be submitted more than once within its hour. Blocking that needs a stored "used" flag, which can come later if needed.
- **Every question must be answered** (`selectedIndex` 0–3). There's no timer in the MVP, so there's no "skipped" value.
- **Quiz `count` is limited to 1–10.** The leaderboard compares raw best scores, so a bigger quiz would be an unfair advantage.
- **Leaderboard:** for each user, best score and number of games in that sport's categories. Sorted by best score, then games played (more is higher), then display name. Ties on best score share a rank (1, 1, 3). `top` is limited to 1–100.
- **History** returns the 50 most recent games, newest first.
- **Emails** are trimmed and lowercased before storing and comparing, so `Kobe@x.com` and `kobe@x.com` are one account. Display names are trimmed and must be 2–30 characters. Passwords must be 8–100 characters.
- **Login failures** return the same 401 message whether the email or the password is wrong, so the API doesn't reveal which emails have accounts.
- **Auth is required by default** (a fallback authorization policy). Only `/auth/*` and `/health` opt out.
- **Register and login return 200** with the auth response, not 201.
- **CORS** allows origins listed in `Cors:AllowedOrigins` (empty by default). The mobile app doesn't need CORS; it's there for a future web client.
- **Category deletes are blocked** while games reference the category, so players' history is never silently lost.
- **Timestamps are UTC**, and JSON timestamps end in `Z`.
- **Tests use the EF Core in-memory provider**, as the plan allows. I also ran every endpoint once against the real SQL Server to check that `NEWID()` ordering and the leaderboard `GROUP BY` translate correctly.

## Phase 2

- **Soccer replaces NBA** (your call). Soccer has two categories: **European Top 5 Leagues** (Premier League, La Liga, Serie A, Bundesliga, Ligue 1, plus the Champions League) and **Internationals** (World Cup, Euros, Copa América, Nations League, women's tournaments). The leagues aren't split into separate categories. That can be done later by moving questions into new files.
- **NFL categories:** History, Records and Stats, Players (the plan's examples).
- **Question count:** 524 at first (Soccer 108 + 117; NFL 96 + 102 + 101).
- **Basketball, Baseball and Hockey added (NBA, MLB, NHL), 881 questions,** with the same three categories as Football: History, Records and Stats, Players. That brings the total to 1,405. The same categories everywhere keep the app predictable and the leaderboards comparable. Each category has 89 to 103 questions; questions that couldn't be verified with confidence were cut rather than padded. Facts that are recent or could change are listed in `seed/REVIEW.md`. The Home "coming soon" cards disappear on their own now that the API returns these sports, and the Leaderboard's sport switcher scrolls sideways to fit five sports.
- **Accuracy over freshness:** I avoided totals that change every week, such as active players' career numbers. Time-sensitive questions are worded "as of 2025" or "through 2024-25". My knowledge stops at mid-2026, so nothing asks about 2025-26 season results. Questions I'm less than very confident about are listed in `seed/REVIEW.md`.
- **Seed layout:** one JSON array per category at `seed/<sport>/<category>.json`. Every item repeats its `sport` and `category`, matching the schema in the plan.
- **The loader syncs rather than just inserting.** Sports and categories are matched by name and questions by exact text within their category. New questions are added, edited ones are updated in place (same ID), and questions deleted from a file are removed from that category. Sports and categories are never deleted, because games reference them. Changing a question's text counts as removing the old question and adding a new one.
- **The loader validates before writing anything.** It applies the same rules as `seed/validate.py` and rejects the whole load if any file is bad.
- **When it runs:** on every startup in Development, which also applies migrations. In production, `dotnet Dykb.Api.dll --seed` applies migrations, syncs the questions, then exits.
- **Seed files ship with the API:** they're copied into the build and publish output (`seed/` next to the DLL), so App Service has them without a separate upload.
- **Each question's correct answer is shuffled into a random slot** when the file is generated, so there's no "it's always B" pattern. Options are not reshuffled for each quiz.

## Branding

- **Brand color:** `#05ff85`. Text and icons on the green are black (15.6:1 contrast). White on the green is only 1.3:1, so it's never used there.
- **Logo (for now):** a classic light bulb with glow rays, black on #05ff85, no text, in the Snapback Sports style. It's an original drawing, so no license or credit is needed. We may upgrade it later; the runner-up was a realistic head in profile with the bulb inside. The source is `design/make_logo.py`; its output is in `mobile/assets/branding/`, as SVG and 1024px PNG, both on green and transparent.
- **App icon and splash** are generated by `flutter_launcher_icons` and `flutter_native_splash` (dev dependencies, configured in `mobile/flutter_launcher_icons.yaml` and `mobile/flutter_native_splash.yaml`). The splash is the bulb centred on #05ff85 with "Do You Know Ball?" at the bottom. Native splash screens can't render live text, so the wordmark is an image (`splash-wordmark.png`). Android 12+ uses the system splash API, which shows the bulb inside a circle; the artwork is sized for that.

## Phase 3: app UI

- **Background color:** soft lavender `#ECEAF6` (your pick). It replaced cream, which looked too much like BALLRS. Lavender is opposite green on the color wheel, so the green pops while the screen stays calm. Cloud `#EEF0F3` and Sky `#E4EDF8` were the alternatives; switching is one line (`AppColors.background`). Green `#05ff85` is the accent (primary buttons). Text is ink `#121212`, and muted text is `#6B6A64`. These live in `mobile/lib/theme.dart`.
- **Font:** Montserrat (replaced DM Sans, which also felt too close to BALLRS). It's bundled in `mobile/assets/fonts/` with its SIL Open Font License (free for apps). It's a variable font, so weights are set through `appFont(size, weight: ...)` in `theme.dart`. The splash text is rendered in Montserrat too.
- **Buttons:** primary buttons are green with ink text and a 2px ink border, which matches the outlined ball icons.
- **Sport ball icons** (soccer, football, basketball, baseball, hockey puck) are original drawings, made by `design/make_ball_icons.py` and rendered to PNG by `design/render_assets.sh`.
- **Welcome screen motion:** the logo and headline fade up, the balls drop in one at a time with a bounce and then bob gently, and the tagline types itself out. The Sign up button and the "Already have an account? Log in" line don't animate (your call: too much motion otherwise). With the system's "Reduce Motion" setting on, everything appears immediately.
- **Navigation:** go_router. Sign up and Log in are placeholder screens until those designs arrive. The "logged in → Home" redirect comes with auth.
- **Sign up and Log in share one screen** (`AuthScreen`) with a sliding toggle, so switching between them animates in place. `/signup` and `/login` just open it in different modes. The style is "sticker": ink outlines with hard offset shadows. Buttons sink when pressed, and a focused field gets a green shadow. The headline has a green marker sweep, a ball (soccer for sign up, football for log in) spins in the corner, sign-up shows a live "8+ characters" check, and errors shake.
- **Client-side validation mirrors the API's rules** (display name 2–30, valid email, password 8+), so most mistakes are caught without a network call. The server's own `{ error }` message is shown for anything else, such as a duplicate email or a wrong password.
- **Session:** the JWT and user are saved with `flutter_secure_storage` (Keychain or Keystore). On launch the native splash stays up until the saved session is read, so returning players go straight to Home. A 401 from any non-auth endpoint signs the player out. The router redirects signed-out players to Welcome and signed-in players to Home.
- **Home is a placeholder** ("You're in, {name}." plus Log out) until the sport-picker design arrives.
- **API address:** `lib/config.dart`, which defaults to `http://localhost:5050` (iOS simulator) or `http://10.0.2.2:5050` (Android emulator). Override with `--dart-define=API_BASE_URL=...`. iOS allows HTTP to local addresses only (`NSAllowsLocalNetworking`). Android allows cleartext only to `10.0.2.2` and `localhost` (`network_security_config.xml`), so production must use HTTPS.

- **Usernames work like Instagram's.** The API's `displayName` field is now a username: 3-30 characters of lowercase letters, numbers, periods and underscores, with no period at the start or end and never two in a row. It's **unique** (409 "That username is taken.") and stored lowercase. The rules live in the API's `UsernameRules.cs` and the app's `username_rules.dart`. The app lowercases what you type and drops characters that aren't allowed, so most mistakes can't even be typed. Usernames show with an `@` ("You're in, @kobe."). The JSON field keeps the name `displayName`, so the API contract didn't change shape.
- **Animated splash:** the native launch screen can't animate, so the app shows its own copy of it (same bulb and text, in the same positions) with a comet-style spinner in between. The hand-off is invisible. While it spins, the app reads the saved login and calls the new **`GET /me`** endpoint. A valid login goes to Home with a refreshed username, and a 401 signs the player out and goes to Welcome. If the API can't be reached within 6 seconds, the saved login is kept rather than kicking an offline player out. The splash stays up at least 0.9s so the spinner never just flickers. With Reduce Motion on, the spinner is a still ring.
- **Password rules (sign-up only):** 8-100 characters; not one repeated character (`11111111`); not a simple run (`12345678`, `abcdefgh`); must not contain the username or the email's name part; not on the common-password list (`api/Dykb.Api/Resources/common-passwords.txt`, about 100 entries; the app's copy is checked against it by a test). This follows NIST guidance: block guessable passwords rather than require symbol and number mixes, so a long non-obvious all-number password is fine. The rules only apply when a password is created, so existing passwords keep working. The sign-up screen shows "8+ characters" and "Hard to guess" checks live, and the second one names the problem.
- **Login accepts email or username.** The request field is now `emailOrUsername` (was `email`). Anything with an `@` after the first character is treated as an email; otherwise it's a username, and a leading `@` is ignored, so `kobe24`, `@Kobe24` and `kobe@example.com` all work. The failure message is "Incorrect username, email or password.", which doesn't reveal which accounts exist.
- **Android launch screen:** Android 12+ forces the launch-screen text image into a fixed 800x320 box (our first, wider image got squashed), so Android has its own 800x320 version with the same text size. The bulb shows at 288dp, the size Android 12+ uses for launch icons, on every Android version. Measured on the emulator, the app's own splash places the bulb and text within 2px of the native screen, so the hand-off doesn't jump. The app releases the native launch screen as soon as its own splash is built: waiting for a frame first can deadlock, because the native screen holds Flutter's first frame back.
- **Instant answer feedback, scored on the server.** Each round is a `QuizAttempt` row: who's playing, which questions were served, and each answer as it's locked in (`QuizAnswers`). `GET /quiz` creates the attempt and returns its id as the `sessionToken`. `POST /quiz/answer` checks one answer, returns right or wrong plus the correct option and a running score, and locks it (409 on a second try, also enforced by a unique index). `POST /games { sessionToken }` scores from the locked answers only, counts unanswered questions as wrong (`selectedIndex: -1` in the review), and works once per round (409 after; a concurrency check covers simultaneous submits). This replaced the encrypted session token and closes the earlier "submit the same quiz twice" gap. Rounds expire an hour after they start.
- **Answer timing is recorded but not scored yet.** The server stores how long each answer took (`ElapsedMs`, measured from the quiz start or the previous answer, so it can't be faked by the app). Scoring stays "correct out of 10" for the MVP; a 15-second timer, speed points and a points-based leaderboard are the planned first upgrade.
- **Bottom navigation:** Home (play), Challenge, Leaderboard, Profile. Challenge (head-to-head games against friends, the core reason for the app) is a placeholder tab with a boxing-glove icon until multiplayer is built; it is in the nav from the start so the app is laid out around it. History was merged into Profile, since history and stats come from the same data. The quiz and results screens are full-screen without the bar.
- **Tabs and navigation:** go_router's `StatefulShellRoute` keeps one navigation stack per tab, so switching tabs and back returns to where you were, and tapping the current tab again goes back to its first screen. The nav bar is a floating white dock with an ink outline and hard shadow. It shows icons only (rounded Material icons: home, history, trophy for the leaderboard, person), with the selected one in a green circle. Screen readers still announce each tab's name. Categories open inside the Home tab (the bar stays); the quiz opens full-screen on top.
- **Home and categories:** sport and category cards are pressable "sticker" cards that stagger in. The sport's ball icon and blurb come from `lib/sports.dart`, since the API only sends names. Every data screen goes through `LoadView`: spinner while loading, a friendly message and a "Try again" button on failure.
- **Shared header:** every tab and the category screen start with the bulb on a green rounded tile (like an app icon) at the left, "dykb?" beside it, and a thin divider (`BrandHeader`). A back button goes before the logo and the sport's ball at the far right.
- **Home** opens with "Welcome @username" in bold, then "Pick your sport." Basketball (NBA), baseball (MLB) and hockey (NHL) show as greyed-out "Coming soon" cards with a lock; they have no questions yet, so tapping one just shows a "coming soon" message. They're client-side only (`SportStyle.comingSoon`) and disappear automatically once the API returns a sport with that name.
- **Profile:** the first letter of the username in a big green circle, then @username in bold and the email smaller, then a smaller red Log out button (white text on `#C62F2F`, 5.5:1 contrast), then "Your stats" with a coming-soon note. There's no real-name field; the username stands in for the name.
- **Leaderboard tab:** "Who knows ball?" with a Football/Soccer switcher (ball icons, selected one green), then each player's best round in that sport from `GET /leaderboard` (top 100). The top three stand on gold, silver and bronze podium blocks, #1 in the middle with a trophy; everyone else is a row with rank, initial, @name, games played and a best-score pill in the results colors. Your spot gets a green "You" tag and tint; if you haven't played that sport, a card nudges you to play a round (it opens that sport's categories), and an empty board says nobody has played yet. Ties share a rank (1, 2, 2, 4), as the API returns. Pull to refresh; it also reloads after a finished round (`GameEvents`).
- **Second font, Fredoka** (rounded and friendly, SIL OFL), used only for the playful touches: the "dykb?" wordmark and the "Welcome @username" line (`funFont` in `theme.dart`). Everything else stays in Montserrat.
- **Green text is always outlined in ink** (`OutlinedText`). Plain #05ff85 on the lavender background is about 1.2:1 contrast, which is unreadable; the ink outline keeps it legible and gives a sticker look. The outline copy is hidden from screen readers so the text isn't read twice.
- **Friendly sport names, shown in the app only:** NFL is shown as Football, NBA as Basketball, MLB as Baseball and NHL as Hockey (`lib/sports.dart`). The database and API keep their names, because the seed loader matches sports by name and renaming one there would create a second, empty sport.
- **Profile = you + stats + recent games.** Everything comes from `GET /games/history`, which now also returns each game's `sportName`. The app works out games played, accuracy (correct answers over questions asked), best round overall and per sport, and lists the 10 most recent rounds; scores of 7/10 or better get a green pill. The history endpoint returns the last 50 games, so stats cover those. Pull down to refresh; Profile also reloads when a round finishes (`GameEvents`, which the quiz screen will trigger). With no games yet, it shows a "Play a round" button instead.
- **Typography is lighter:** headings use weight 700, titles and buttons 600, body 400-500, and sizes came down 10-20% (big headlines 32, card titles 20). Only the avatar letter and the "dykb?" wordmark stay extra-bold.
- **Quiz round (`QuizScreen`):** full-screen, no nav bar. A 3-2-1 intro with the sport's ball bobbing; the questions load during the countdown. Each question has a 10-segment progress bar (green right, red wrong), a score pill that pops when it goes up, the question on a cream card (`AppColors.cream`, #F4F1EA) and four answers with colored letters (A yellow, B blue, C orange, D pink; never green or red, which mean right and wrong). A pick is sent to `POST /quiz/answer` and the button shows a spinner until the server replies; the app never knows the answers. Right: the button turns green and a dark "Nice! / You know ball." bar slides up. Wrong: the pick shakes red, the right answer turns green, and the bar says "Not quite / Lock in twin". It moves on by itself (1.5 s right, 2.2 s wrong) or with Next. Leaving mid-round (the ✕ or the system back gesture) asks first, and the auto-advance pauses while it asks.
- **Results (`ResultsView`):** the round is submitted with `POST /games`, then `GameEvents.gameFinished()` reloads Profile. The score sits in a ring colored by score: red 0-4, yellow 5-7, green 8-10 (`AppColors.forScore`), with confetti for 8+. The headline follows the same bands: "Do you though?", "You know some ball.", "You know ball.", and "Certified ball knower." for 10. Three cream tiles: Your best in this category (from history, excluding this game; "New" when beaten), longest Streak, and Rank in the sport (from the leaderboard; "–" if you're outside the top 100 or it can't load). Accuracy was dropped as redundant with the score; Time will join when timers arrive. Buttons: Play again, Challenge a friend (marked Soon), Back to Home. Every question is recapped: green check, or a red X with your pick crossed out next to the answer.
- **Profile score pills** now use the same bands: green 8+, yellow 5-7, soft red below.
- **How a round's questions are picked (`QuizService.PickQuestions`):** a balanced mix of 40% easy, 40% medium, 20% hard (4/4/2 in a round of 10), chosen at random. Questions from the player's last 3 rounds in that category are held back while fresh ones remain, and a short difficulty is topped up from the others, so a round is always full. Picking happens in memory, since a category holds about 100 questions. Rounds are presented in random order, not easy-to-hard.
- **Answer options are shuffled per round.** Each attempt stores its shuffle (`QuizAttempt.OptionOrders`, four digits per question), so the same question shows its options in a different order each time and answers can't be learned by position. Everything the client sends and receives uses the shown positions (`selectedIndex`, `correctIndex`, the review); the server maps them back to the stored order. Rounds started before this change have no stored shuffle and use the original order.
- **XP, levels and ranks (built).** The server awards XP when it scores a round: +10 per correct answer, +20 for finishing, +30 more for a perfect round (`Levels.ForRound`), and stores it on the game (`GameSession.XpEarned`; older games were backfilled by the migration). Level 2 takes 300 XP, level 3 another 500, and every level after that 1,000, so a new player levels up after about 4 rounds and YKB (level 100) is 97,800 XP, about 1,090 rounds. (First built as 100 XP plus 25 more per level, then a flat 1,000; the quick first two levels keep new players hooked.) Ranks by level: Waterboy (1-4), Benchwarmer (5-9), Casual (10-19), Real Fan (20-29), Certified (30-49), Unc (50-74), GOAT (75-99), YKB, "You Know Ball" (100+). `GET /me/progress` returns XP, level, progress into the level and rank; `POST /games` also returns the XP breakdown and the progress before and after the round.
- **Rank badges:** the bulb logo drawn in code (`RankBulb`), glowing in the rank's color with more rays at higher ranks (unlit for Waterboy and Benchwarmer; YKB is black with a green bulb). Shown as a shield (`RankShield`) or a pill with the name (`RankPill`, with a smaller version for leaderboard rows). Badges and XP bars have a soft sheen that sweeps across every few seconds (`Sheen`), off when Reduce Motion is on.
- **Where progress shows:** Home puts the shield after "Welcome @user", with the rank pill and level on the left and the XP count (small, light) on the right above a slim bar in the rank's color. Tapping it opens the rank ladder (passed ranks checked, yours highlighted, higher ones locked). Profile shows the shield on the avatar, the same level line, and a Total XP tile in place of Accuracy. Results adds an "XP earned" card with the breakdown and the bar; a round that crosses a level shows a full-screen "Level up", or a bigger "New rank unlocked" when it crosses into a new rank.
- **Leaderboards rank by XP, top 10:** a Global tab (all sports) and one tab per sport (XP earned in that sport, with best score shown under the XP). XP rewards playing often and well; best score alone ties up at 10/10 quickly. Rows are spaced out with light text: position (medals for the top 3), rank shield, name with "Lvl N" and a small rank pill, XP on the right. #1's name shimmers in gold with a crown. If you're outside the top 10, `GET /leaderboard` also returns your row (`me`) and the app pins it under the list. Ties share a rank. A weekly board was discussed but not built.
- **Font sizes stay small and light** in these screens (the user prefers it); see the font sizes in `rank_badges.dart` and `leaderboard_screen.dart` when adjusting.
- **Production on Azure, free tiers ($0/month):** App Service F1 (Linux, .NET 10) and the Azure SQL Database free offer (serverless, auto-pauses instead of charging if the monthly free compute runs out). Everything is in Central US because East US 2 and East US weren't accepting new SQL servers for this new subscription. Production has its own JWT key; secrets live only in App Service settings. Migrations and seeding run from the developer machine with `--seed` (`infra/deploy.sh --seed`) rather than on app startup, so a deploy never changes the schema by surprise. Release builds of the app use the Azure URL (`AppConfig.production`); debug runs stay on the local API. Swagger stays on in production as API docs; every endpoint except register, login and health still requires a token. Details in `infra/deploy.md`.
- **Database retries:** the API retries failed database connections (EF Core `EnableRetryOnFailure`, up to 10 times, at most 15 seconds apart). The free Azure SQL tier pauses when idle and refuses connections with error 40613 while it resumes. This first showed up as a failed deploy, when the seed step ran against a paused database. It also keeps a player's first request after a quiet spell from failing.
- **API host upgraded to B1 with Always On** (about $13/month, Linux, Central US) after the subscription was upgraded, to use the $200 trial credit. The API no longer sleeps; the database stays on the free tier, and connection retries cover its wake-up. Revisit before the credit runs out (about 30 days after sign-up): keep B1, or go back to F1 with one command.
- **Database moved to Basic** (5 DTUs, 2 GB, about $4.90/month, $0.161/day) so it never pauses; the data is about 8 MB. Moving off the free serverless offer needed `--use-free-limit false`. Going back to the free offer would mean creating a new free database and copying the data over. With the B1 API host, production runs about $18/month, covered by the trial credit until it expires.
- **Web version on Azure Static Web Apps** (Free) instead of Vercel, to keep everything in one Azure account: https://jolly-stone-01f7ca410.3.azurestaticapps.net. The same Flutter code builds for the web (`flutter build web`); the API allows the site through CORS (`Cors__AllowedOrigins__0`). A GitHub Action rebuilds and publishes it on pushes that change the app. On the web, logins are kept in browser storage and taps don't vibrate.
- **Slimmer, roomier layout (late October 2026).** Everything chunky came down about 10-20% so phones like the iPhone 16 feel as roomy as a Pro Max, without shrinking body text: page side padding 24 to 20, header logo tile 46 to 38, big headlines 32 to 27, sport cards (ball 62 to 46, name 20 to 17, blurb on one line) with 12 between them, buttons 58 to 52 tall, nav bar 66 to 58, quiz question card and answers a step smaller, results ring 176 to 148, profile avatar 104 to 84. All five sports now fit on the iPhone 16 home screen. `test/screens_capture_test.dart` renders the main screens to PNGs with the real fonts for before/after reviews (`CAPTURE_DIR=... flutter test test/screens_capture_test.dart`; skipped otherwise).
